📌 Stickies — README

A private, offline-first sticky-notes app for desktop and mobile.

No build step, no framework, and no server are required. The app is a static PWA centered around a single index.html plus the files needed for installation and offline caching.

Offline-first • Installable PWA • Optional Google Drive sync

Everyday data & privacy

Every sticky lives in your browser's local storage. Nothing is sent anywhere unless you explicitly connect your Google account for optional Google Drive sync.

The official Stickies deployment already has Google OAuth configured, so normal users do not need to create or enter an OAuth Client ID.

Features

  • Free placement on an unlimited, scrollable desktop canvas — drag stickies anywhere; drop one near another and it can align without overlapping when that behavior is enabled in Settings.
  • 9 built-in color themes plus a custom color picker, with a per-sticky transparency slider.
  • Rich text with 4 font families, 5 sizes, bold, italic, underline, strikethrough, bullets, numbering, and Markdown-style list behavior.
  • Checklists: type [] or [x] at the start of a line to create a clickable checklist box, then click the box to toggle it.
  • Resize, minimize/expand, lock, and pin. Locked stickies cannot be modified until they are unlocked. Pinned stickies occupy the upper layer tier, above unpinned stickies; layer order is maintained within the pinned and unpinned tiers.
  • Groups sidebar with color-coded groups and an Unassigned bucket. The sidebar can be collapsed with ⮜ and shown again with ⮞ to give the canvas more room.
  • Search that filters and highlights matches across titles, content, tags, and group names.
  • Auto-organize: tile, cascade, compact, or cluster by group/color. Locked and pinned stickies are left in place.
  • Sticky Manager — a sortable list view for bulk moving, deleting, exporting, importing, and editing stickies.
  • Trash with restore, an installable offline PWA, and optional Google Drive sync.

Running it locally

No build step is needed. You can open index.html directly in a browser, or serve the folder with any static file server, for example:

npx serve .
# or
python3 -m http.server 8080
Tip: PWA installation and some browser features work best when the app is served over HTTP/HTTPS rather than opened directly from a file:// URL.

Deploying to GitHub Pages

  1. Push this repository to GitHub.
  2. In Settings → Pages, set the source to GitHub Actions.
  3. The included workflow (.github/workflows/deploy.yml) deploys on every push to main. There is no build step; the static files are published as-is.
  4. The official deployment is available at https://bkar81.github.io/stickies/.
  5. On a phone or supported desktop browser, you can install Stickies from the browser's Add to Home Screen / Install option. Once installed, the app can run offline using its cached PWA shell.

Google Drive sync — optional

Google Drive sync is off by default. The official Stickies deployment already contains its authorized Google OAuth configuration. You simply open Settings → Google Drive sync and connect your Google account when you want cloud backup.

For users of the official Stickies deployment: you do not need to create, copy, or enter a Google OAuth Client ID. The Client ID is already configured in the official app.

What is synchronized?

Stickies backs up your data to your own Google Drive in a single stickies-notes-data.json file. The sync uses the drive.file scope, so the app can access the file it creates rather than your entire Drive.

Merging is timestamp-based: for a sticky, the version with the newest updatedAt wins. This is intended to allow the same Stickies data to be synchronized across your devices.

If you fork or self-host Stickies

A fork or separately deployed copy should use its own Google OAuth Client ID. Do not reuse the OAuth configuration belonging to the official deployment.

  1. Create or select a project in Google Cloud Console.
  2. Enable the Google Drive API for that project.
  3. Configure the project's OAuth consent screen. If the app remains in Testing mode, add the Google accounts that will use it as test users.
  4. Create Credentials → OAuth client ID with application type Web application.
  5. Add the origin of your deployed app to Authorized JavaScript origins.
  6. Update the STICKIES_GOOGLE_CLIENT_ID value in index.html with the Client ID belonging to your own Google Cloud project.
  7. Deploy the fork, then use Settings → Google Drive sync → Connect in that deployment.

The exact OAuth configuration can vary depending on how and where a fork is hosted, so the Google Cloud project and authorized origin must match that deployment.

Important notes

  • Reset App Data is destructive. It restores the app to its default data state. Export your JSON first if you want a backup of your current local stickies.
  • Deleting a sticky moves it to Trash first, where it can be restored until it is permanently removed.
  • Locking is separate from pinning: a locked sticky cannot be edited, moved, renamed, resized, recolored, minimized/expanded, or otherwise modified until it is unlocked. Pinning controls the sticky's layer tier and does not itself lock the sticky.
